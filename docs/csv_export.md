# CSV export

`scripts/generate_csv_insights.py` exports processed case records from the processed S3 bucket to a CSV file for Power BI, Excel and other tools that do not use Athena. It writes one row per processed case with the account number and all 18 processed-record fields.

Athena is not used or required. The exporter lists and reads the processed records directly from S3, so it works with `enableAnalytics` set to `false`, needs no Glue or Athena permissions, and includes newly processed cases straight away without waiting for the Glue crawler.

The exporter is tested locally against synthetic records in `test/scripts/test_generate_csv_insights.py` (moto S3 and botocore Stubber). An export from a real deployed bucket has not been run; it is deferred with the rest of the live AWS acceptance.

## Prerequisites

- A checkout of this repository. The script imports the RCA and lifecycle taxonomies from `src/lambda/common/taxonomy.py` to validate category filters.
- Python 3.12 with the hash-locked development requirements, which include the pinned `boto3` and `pandas` versions the script uses:

  ```bash
  python3.12 -m venv .venv
  .venv/bin/python -m pip install --require-hashes -r requirements-dev.txt
  ```

- AWS credentials for the management account from the standard credential provider chain: environment variables, `--profile` or `AWS_PROFILE`, IAM Identity Center (`aws sso login`), or an instance or container role. The script never reads credentials from its own options or files.

## Find the processed bucket

The processed bucket has a name generated by CloudFormation. Look it up in the Core stack:

```bash
aws cloudformation list-stack-resources --stack-name CaseInsightsCoreStack-<uniqueId> \
  --query "StackResourceSummaries[?ResourceType=='AWS::S3::Bucket' && starts_with(LogicalResourceId, 'StorageProcessedBucket')].PhysicalResourceId" \
  --output text
```

## Required permissions

The exporter makes only two kinds of S3 request, matching the `--help` text:

| Permission | Resource | Used for |
| --- | --- | --- |
| `s3:ListBucket` | `arn:aws:s3:::<bucket>` | Listing `account_number=` prefixes (`ListObjectsV2`) |
| `s3:GetObject` | `arn:aws:s3:::<bucket>/account_number=*` | Reading each `data.json` record |

An identity policy for the exporting user or role:

```json
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Sid": "ListProcessedRecords",
      "Effect": "Allow",
      "Action": "s3:ListBucket",
      "Resource": "arn:aws:s3:::<bucket>"
    },
    {
      "Sid": "ReadProcessedRecords",
      "Effect": "Allow",
      "Action": "s3:GetObject",
      "Resource": "arn:aws:s3:::<bucket>/account_number=*"
    }
  ]
}
```

- The principal must be in the management account: the processed bucket policy grants nothing to other accounts.
- The bucket uses SSE-S3, so no AWS KMS permissions are needed.
- The bucket policy denies requests without TLS 1.2 or later. The script uses HTTPS through boto3, so no setting is needed.
- When access is denied the script exits with status `3` and names the missing permission, for example `The caller needs s3:GetObject on arn:aws:s3:::<bucket>/account_number=*.`

## Usage

Show every option and the permissions summary (no AWS access needed):

```bash
.venv/bin/python scripts/generate_csv_insights.py --help
```

Export everything to a file:

```bash
.venv/bin/python scripts/generate_csv_insights.py \
  --bucket <bucket> --output case-insights.csv --profile <profile> --region <region>
```

Export one account's cases created in the first half of 2026, replacing an earlier file:

```bash
.venv/bin/python scripts/generate_csv_insights.py \
  --bucket <bucket> --account-id 123456789012 \
  --start-date 2026-01-01 --end-date 2026-06-30 \
  --output account-123456789012-h1.csv --overwrite
```

Export throttling and quota cases of two services that were classified in the last week, as UTF-8 with a byte-order mark for Excel:

```bash
.venv/bin/python scripts/generate_csv_insights.py \
  --bucket <bucket> \
  --rca-category Throttling --rca-category "Limit reached" \
  --service-code amazon-dynamodb --service-code aws-lambda \
  --date-field RCA_Retrieval_Date --start-date 2026-11-06 --end-date 2026-11-12 \
  --encoding utf-8-sig --output throttling.csv
```

Labels that contain spaces must be quoted in the shell.

## Options

| Option | Default | Description |
| --- | --- | --- |
| `--bucket BUCKET` | Required | Processed-record bucket name. Must be a valid S3 bucket name. |
| `--output OUTPUT` | `-` (standard output) | CSV file to write. The directory must exist. Files are written to a temporary file in the same directory and then atomically moved into place, so a reader never sees a partial file, and are created with owner-only permissions (`0600`). Without `--overwrite` the file is published with a hard link, which never replaces an existing file, so the directory's filesystem must support hard links. |
| `--overwrite` | Off | Replace `--output` if it already exists. Without it the script refuses to run (status `2`), and a file that another process creates at that path while the export runs is left unchanged (status `2`, nothing written). |
| `--account-id ID` | All accounts | Export only this 12-digit account. Repeatable. Only the selected accounts' `account_number=<id>/` prefixes are listed, so this also reduces S3 requests. |
| `--start-date YYYY-MM-DD` | No lower bound | Earliest UTC calendar day, inclusive. Must not be after `--end-date`. |
| `--end-date YYYY-MM-DD` | No upper bound | Latest UTC calendar day, inclusive. |
| `--date-field` | `timeCreated` | Record date the date range applies to: `timeCreated` (case creation), `Case_Retrieval_Date`, `RCA_Retrieval_Date` or `Lifecycle_Retrieval_Date`. |
| `--rca-category LABEL` | All | Export only this `RCA_Category`: an RCA taxonomy label or `Unclassified`. Repeatable. Unknown labels are rejected with the list of valid values. |
| `--lifecycle-category LABEL` | All | Export only this `Lifecycle_Category`: a lifecycle taxonomy label or `Unclassified`. Repeatable. |
| `--service-code CODE` | All | Export only this `serviceCode`, for example `amazon-simple-storage-service`. Repeatable. At most 256 characters. |
| `--severity-code CODE` | All | Export only this `severityCode`, for example `low` or `urgent`. Repeatable. At most 256 characters. |
| `--max-records MAX_RECORDS` | `100000` | Fail with status `4`, writing nothing, when more records match. Accepts 1 to `1000000`. Only matching records count. |
| `--skip-invalid` | Off | Skip objects that are not valid processed records instead of failing. Their keys and reason codes are listed on standard error. |
| `--encoding` | `utf-8` | `utf-8`, or `utf-8-sig` to add a byte-order mark so older Excel versions detect UTF-8 when the file is opened directly. |
| `--no-escape-formulas` | Off | Write values verbatim. By default a value starting with `=`, `+`, `-`, `@`, a tab or a carriage return is prefixed with a single quote (`'`) so spreadsheets do not run it as a formula. |
| `--page-size PAGE_SIZE` | `1000` | Keys per S3 list request, 1 to 1000. |
| `--max-workers MAX_WORKERS` | `8` | Parallel S3 object reads, 1 to 32. |
| `--region REGION` | From AWS configuration | Region of the bucket (the deployment `region`). |
| `--profile PROFILE` | From AWS configuration | AWS named profile. |

## Filtering

- Different filters combine with AND; repeating one filter option matches any of its values (OR). For example `--severity-code urgent --severity-code critical --service-code aws-lambda` exports urgent or critical Lambda cases.
- Dates are compared as UTC calendar days on the field chosen by `--date-field`; both bounds are inclusive.
- Category, service and severity filters are exact, case-sensitive matches. A record whose `serviceCode` or `severityCode` is null never matches a value filter for that field.
- Only `--account-id` narrows what is listed. Every other filter is applied after a record is read, so S3 `GetObject` requests grow with the number of records in the selected accounts, not with the number of matches.
- Every object is validated against the 18-field processed-record schema and its key before it is filtered. Objects outside the `account_number=<id>/case_number=<displayId>/data.json` layout are ignored and counted.

## Output

The file has a header row and one row per record, comma separated, with fields quoted only when needed (for example summaries that contain commas) and CRLF line endings. Null values are empty cells. Rows are sorted by `account_number`, case creation time (`timeCreated`) and `displayId`, so repeated exports of unchanged data are identical.

The header row is:

```text
account_number,caseId,displayId,subject,serviceCode,categoryCode,severityCode,submittedBy,timeCreated,Case_Retrieval_Date,Case_Summary,RCA_Category,RCA_Reason,RCA_Retrieval_Date,Lifecycle_Category,Lifecycle_Reason,Lifecycle_Retrieval_Date,Model_Id,Prompt_Version
```

| # | Column | Content |
| --- | --- | --- |
| 1 | `account_number` | 12-digit account ID taken from the S3 key (records have no account field). Keep it as text: IDs can start with zero |
| 2 | `caseId` | Support case ID |
| 3 | `displayId` | Case number shown in the Support Center |
| 4 | `subject` | Case subject (may be empty) |
| 5 | `serviceCode` | Support service code (may be empty) |
| 6 | `categoryCode` | Support category code (may be empty) |
| 7 | `severityCode` | `low`, `normal`, `high`, `urgent` or `critical` (may be empty) |
| 8 | `submittedBy` | Submitter identity, personal data (may be empty) |
| 9 | `timeCreated` | Case creation time, ISO-8601 UTC, for example `2026-06-01T10:00:00.000Z` |
| 10 | `Case_Retrieval_Date` | Retrieval time, `YYYY-MM-DDTHH:MM:SSZ` |
| 11 | `Case_Summary` | Plain-prose summary of 600 to 650 characters |
| 12 | `RCA_Category` | RCA category or `Unclassified` |
| 13 | `RCA_Reason` | Explanation of the RCA category |
| 14 | `RCA_Retrieval_Date` | RCA classification time, `YYYY-MM-DDTHH:MM:SSZ` |
| 15 | `Lifecycle_Category` | Lifecycle category or `Unclassified` |
| 16 | `Lifecycle_Reason` | Explanation of the lifecycle category |
| 17 | `Lifecycle_Retrieval_Date` | Lifecycle classification time, `YYYY-MM-DDTHH:MM:SSZ` |
| 18 | `Model_Id` | Bedrock inference profile that produced the record |
| 19 | `Prompt_Version` | `pv-` followed by the prompt and taxonomy digest |

The categories and their definitions are listed in [Athena analytics](athena.md#classification-values).

Counts go to standard error and never include record content. This is the output of a local run against a synthetic bucket with three valid records and one malformed object:

```text
Skipped 1 invalid records:
  account_number=012345678901/case_number=1003/data.json: malformed_json
Listed 4 objects; 0 non-record objects ignored.
0 records filtered out; 0 records removed during export.
1 invalid records skipped.
Exported 3 records to case-insights.csv.
```

Without `--skip-invalid`, the same run lists the invalid key as `Found 1 invalid records:`, writes nothing and exits with status `4`. Invalid-record reason codes are `malformed_json`, `not_an_object`, `field_set`, `not_a_string`, `missing_value`, `display_id_mismatch`, `invalid_date` and `too_large` (over 1 MiB). Up to 50 keys are listed. A record deleted between listing and reading is counted as removed during export and skipped.

The CSV contains case summaries, subjects and submitter identities. Store it with the same care as the processed bucket and delete copies that are no longer needed.

## Exit status

| Status | Meaning |
| --- | --- |
| `0` | Export written |
| `2` | Invalid options, for example an unknown category, a start date after the end date, a missing output directory or an existing output file without `--overwrite`. No AWS request is made, except when the output file appears while the export runs; that file is left unchanged |
| `3` | AWS error: missing credentials, unknown profile, access denied (the message names `s3:ListBucket` or `s3:GetObject`), missing bucket (`NoSuchBucket`; check `--bucket` and `--region`) or another S3 failure |
| `4` | Invalid records found without `--skip-invalid`, or more than `--max-records` records match |

No output file is written unless the export succeeds.

## Scheduling

The exporter is a command-line tool; no scheduled export is deployed. To refresh a file regularly, run it from cron, a systemd timer, Windows Task Scheduler or a CI job on a host with credentials for the management account. Use a role (instance profile, container role or a dedicated profile) rather than interactive sign-in for unattended runs.

- Account discovery starts at 00:00 UTC by default, and the daily run is finished when the `DailyRunCompleted` heartbeat is emitted. Schedule the export after your runs usually complete; an earlier export simply contains the records committed so far. The export does not depend on the Glue crawler.
- Use `--overwrite` so each run atomically replaces the previous file; readers such as Power BI see either the old or the new file, never a partial one.
- Treat a non-zero exit status as a failed refresh and alert on it. The previous file is left unchanged.
- The file is created with mode `0600`. If another account (for example a Power BI gateway service) must read it, grant that access deliberately, for example through a directory group, rather than widening the mode for everyone.

Example crontab entry running at 06:30 UTC on a Linux host (the host clock or `CRON_TZ` must be UTC):

```bash
30 6 * * * cd /opt/factorytestsample && .venv/bin/python scripts/generate_csv_insights.py --bucket <bucket> --region <region> --profile case-insights-export --output /srv/exports/case-insights.csv --overwrite >> /var/log/case-insights-export.log 2>&1
```

## Power BI

1. In Power BI Desktop choose **Get data**, **Text/CSV** and select the exported file.
2. In the preview set **File origin** to `65001: Unicode (UTF-8)` and **Delimiter** to **Comma**, set data type detection to **Do not detect data types**, then choose **Transform Data**.
3. In Power Query, set column types explicitly:
   - `account_number`, `caseId` and `displayId` as **Text**, so account IDs keep leading zeros and case numbers are not summed;
   - `timeCreated`, `Case_Retrieval_Date`, `RCA_Retrieval_Date` and `Lifecycle_Retrieval_Date` as **Date/Time/Timezone** (they end in `Z`, meaning UTC), then convert to **Date/Time** if you prefer local display;
   - every other column as **Text**.
4. Add helper columns as needed, for example `Date.DayOfWeekName([timeCreated])`, `Date.StartOfMonth([timeCreated])` or a week-of-month column `Number.IntegerDivide(Date.Day([timeCreated]) - 1, 7) + 1`.
5. Build visuals that match the Athena query library: RCA distribution on `RCA_Category`, a matrix of `serviceCode` against `Lifecycle_Category`, cases by weekday, week of month and month, `severityCode` by month, and the top accounts by count of `caseId`.
6. **Refresh.** Power BI Desktop rereads the file on **Refresh**. Scheduled refresh in the Power BI service needs the file to be reachable, either through an on-premises data gateway on the host that holds the file or by copying the file to OneDrive or SharePoint. Copying it there moves case content into that service, which is a data-governance decision for your organisation. Schedule the refresh after the export job.

By default, values that start with `=`, `+`, `-`, `@`, a tab or a carriage return are written with a leading `'`, which Power BI shows as part of the text. Use `--no-escape-formulas` only for files that are consumed solely by Power BI and are never opened in a spreadsheet.

## Excel

- **Recommended: import with Power Query.** Choose **Data**, **From Text/CSV**, select the file, set **File origin** to `65001: Unicode (UTF-8)`, choose **Transform Data** and set the same column types as for Power BI. In particular keep `account_number` as **Text**. Load the result as a table and use **Data**, **Refresh All** after a scheduled export replaces the file. Pivot tables on that table reproduce the query library views.
- **Opening the file directly.** Double-clicking a CSV makes Excel guess column types: 12-digit account numbers become numbers, which drops leading zeros and may show them in scientific notation, and dates are reinterpreted. Use Power Query for analysis. If people do open files directly, export with `--encoding utf-8-sig` so non-ASCII characters display correctly.
- **Formula protection.** Keep the default formula escaping for any file that may be opened in a spreadsheet: case subjects and summaries come from customer-written text, and the escaping stops a value such as `=HYPERLINK(...)` from running as a formula.
- **Size.** An Excel worksheet holds 1,048,576 rows, so the largest permitted export (`--max-records 1000000`) fits on one sheet. Summaries are well below Excel's 32,767-character cell limit.

## Troubleshooting

| Symptom | Fix |
| --- | --- |
| Status `3`, `AWS credentials were not found` | Configure the credential provider chain, for example with `--profile`, `AWS_PROFILE` or `aws sso login`. |
| Status `3`, `AccessDenied` naming `s3:ListBucket` or `s3:GetObject` | Grant the permission named in the message on the resource shown (see [Required permissions](#required-permissions)), using a principal in the management account. |
| Status `3`, `NoSuchBucket` | Check `--bucket` against the Core stack lookup and set `--region` to the deployment Region. |
| Status `4`, invalid records | Inspect the listed keys and reason codes. Use `--skip-invalid` to export the valid records while investigating. |
| Status `4`, more than `--max-records` records match | Narrow the filters (for example `--account-id` or a date range) or raise `--max-records` up to `1000000`. |
| Account IDs lose leading zeros | The file was opened without type control; import it with Power Query and set `account_number` to **Text**. |
| Recent cases are missing | Only committed processed records are exported. Cases that are still being analysed, or failed, appear after a later run commits them. |
